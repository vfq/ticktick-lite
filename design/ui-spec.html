滴答 Lite · 界面设计方案

380×620 桌面悬浮小窗的效率工具界面。设计目标：一屏之内完成「看 — 加 — 做 — 收」闭环，把最高频操作放在最短路径上，用颜色与分组双编码传达优先级。

设计原则

  • 零学习成本：清单、勾选、时间段沿用 TickTick 心智模型
  • 高频优先：快速添加常驻顶部，回车即创建
  • 可扫读：优先级分组 + 左侧色条，一眼定位要事
  • 一屏闭环：日常操作（加 / 勾 / 编 / 筛）全在主窗内完成，编辑类走轻量覆盖层
  • 配置外置：低频配置不挤占小窗，收进独立设置窗口
  • 克制动效：150ms 过渡，仅用于状态确认

信息架构

  • 标题栏 40px：拖拽 · 🍅 番茄钟 · ⚙ 设置 · 置顶 · 最小化到托盘
  • 快速添加 52px：常驻输入框
  • 清单切换 36px：横向 chip + 计数
  • 工具条 28px：计数 · 已完成 · 导出
  • 标签筛选条：仅有选中标签时出现
  • 任务列表：优先级分组滚动区
  • 番茄钟：右下角浮层，默认收起，不占常驻高度

符合习惯的交互

  • Enter 快速添加 / 保存编辑
  • Esc 关闭覆盖层
  • 点击勾选框切换完成，点击行进入编辑
  • 行内悬停出现：专注 · 编辑 · 删除
  • 关闭按钮 = 隐藏到托盘，退出走托盘菜单

设置窗口（独立窗口）

设置不再是主窗覆盖层，而是独立窗口（440×560，自绘 34px 标题栏，可拖动）。 左侧固定 104px 导航，右侧内容区独立滚动；所有改动即时生效并落库，没有「保存」按钮。 同一时刻只允许一个设置窗：再次点 ⚙ 只把已存在的窗口提到前台。

三处必须遵守的一致性

  • 单一真相：主窗与设置窗共享同一个 SettingsStore 实体，任一侧改动都会 emit 后双向同步。
  • 即时保存：改动即 clamp（越界钳制而非报错）→ 落库 → 广播，不设「应用」按钮。
  • 标签分区：新建 / 改名 / 点色点展开 8 色板 / 删除需二次确认（文案明确「任务本身不会被删除」）。

番茄钟浮层的两条约束

  • 默认收起：收起态卡片不渲染，右下角也不占位，任务列表拿回完整高度。
  • 收起不打断：计时仍在跑，倒计时改为显示在标题栏 🍅 位置。

可访问性

  • 正文 #1F2328 对白底对比度 15.3:1，次级 #6B7280 为 4.8:1，均达 WCAG AA。
  • #9CA3AF 仅用于图标与极弱提示，不承载关键文本。
  • 优先级同时使用颜色与分组标题双编码，不依赖单一颜色传递信息。
  • 所有交互可用键盘达成，焦点始终可见（2px 主色描边）。
  • 尊重系统「减弱动效」偏好，关闭非必要过渡。

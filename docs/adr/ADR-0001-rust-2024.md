# ADR-0001 迁移到 Rust 2024 edition

## 背景

三个 crate（`ticktick-core` / `ticktick-app` / `ticktick-plugin-pomodoro`）都通过
`edition.workspace = true` 继承根 `Cargo.toml` 的 `edition = "2021"` 与 `resolver = "2"`。
工具链锁定 `1.98`，早已满足 2024 edition 要求的 rustc ≥ 1.85。

依赖侧 `gpui-kit 0.8.1` 本身已是 2024 edition，主工程与之不一致没有收益。

## 决策

1. 根 `Cargo.toml` 改 `edition = "2024"`；三个 member 不动（继承生效）。
2. `resolver = "2"` → `"3"`。edition 2024 自 Cargo 1.84 起默认 resolver v3，
   显式写 2 会保留旧的 feature 合并行为，与 edition 声明的语义不一致。
3. 不逐 crate 覆盖 edition——单一来源，避免三处配置熵。

## 代码层面的影响评估（已逐项 grep 核实）

| 2024 破坏性变更 | 本项目命中 | 说明 |
|---|---|---|
| `unsafe_op_in_unsafe_fn` 变 hard error | 否 | 全仓库只有 3 处 `unsafe {}` 块（`platform.rs:27/36/45`），均在安全函数内，**无 `unsafe fn`** |
| `gen` 成保留字 | 否 | 无 `gen` 标识符 |
| match ergonomics 限制 `ref`/`ref mut`/`mut` 修饰符 | 否 | 无 `ref` 模式，全是纯解构 |
| `static mut` 引用禁止 | 否 | 无 `static mut` |
| `unsafe extern` 块 | 否 | 无 `extern` 块 |
| `std::env::set_var` 变 unsafe | 否 | 无调用 |
| `if let` 临时值析构顺序收紧 | 低风险 | 26 处 `if let` 均为"绑定借用后立即读取"，不依赖临时值存活 |
| RPIT 生命周期捕获扩大 | 否 | 唯一 RPIT 是 `fn render(...) -> impl IntoElement`，返回 owned `Div` |

## 后果

**正面**
- 与依赖 edition 对齐，避免跨 edition 的宏/语义差异。
- 获得 2024 的 `if let` 作用域收紧与更严格的 unsafe 语义（对后续加 FFI 是保护）。

**负面 / 代价**
- `Cargo.lock` 会因 resolver v3 重新解析，需一并提交。
- 本机按 [ADR-0002](ADR-0002-ci-self-hosted-qc.md) 只跑 `cargo fmt`，
  因此 edition 升级的**编译正确性由 CI 的 `clippy (core)` / `test (core)` 证明**——
  这两个 job 覆盖 core crate，足以代表 2024 语义下的编译结果；app / plugin 侧
  依赖阶段验收时的本机 `cargo check`。

## 替代方案

1. **保持 2021** —— 与依赖 edition 不一致，且没有任何收益，否决。
2. **逐 crate 升级** —— 增加三处配置来源，收益为零，否决。

## 实施顺序

必须先改 edition 再 `cargo fmt --all`，否则会格式化两遍。
